## Integer bounds decision

`services/invasion.py:37` defines `MAX_SIGNED_INTEGER = (1 << 31) - 1` (**2,147,483,647**), used inside its own V1 service for validated counts, stage and wave sequence. `services/maintenance/service.py:16` also imports it and applies it to the V1 `invasion_wave_count`, `invasion_enemy_base_power`, and `invasion_enemy_activity_bonus_cap` configuration limits (lines 336, 354, 357); this is the *external runtime import that must be resolved* before removing the module. The same import includes `LEGACY_WAVE_COUNT = 2`, used by V1 enemy-power scaling (maintenance line 420). `keyboards/invasion.py` has a **separate local** `_MAX_SIGNED_INTEGER = (1 << 31) - 1` for V1 callback wave sequences (lines 35, 77), plus local 64-bit `_MAX_SIGNED_BIGINT` for IDs; it does **not** import the service constant. No other non-documentation usages of uppercase `MAX_SIGNED_INTEGER` were found. **Recommendation:** remove the V1 maintenance validators/scaler along with the old cycle, then delete the service and keyboard constants with their owners; do **not** relocate either to a shared module unless a surviving V2/shared caller is identified in the final audit. If one genuinely remains, give that caller an appropriately named, independently tested DB-bound constant (e.g. a common DB limits module), not an import from V1. Do not substitute `MAX_SIGNED_BIGINT` for a 32-bit wave bound.

## V2 wiring test decision

**Rewrite, not delete** `tests/invasion_v2/test_wiring.py`. Its functional contract is that disabled maintenance/recovery do not invoke V2, enabled maintenance invokes exactly one `InvasionScheduler.tick`, enabled recovery invokes exactly one `InvasionScheduler.recover`, and worker startup logs the resolver once. `InvasionTelegramService` import and `run_invasion_cycle`/`publish_maintenance_updates` monkeypatches/assertions only prove old code is dormant; they will fail to import/patch once removed. Keep all V2 gate and resolver assertions, remove old-code coupling, and supplement with an import/static audit for accidentally reintroduced V1 calls if desired. Avoid replacing with no-op assertions that no longer test the production entry points.
